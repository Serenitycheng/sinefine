## 由用户完成正式发布

用户认可的建议流程是：`feat/art-samples` 继续开发并自动生成预览，`main` 保持正式版；每批验收后由用户普通合入 `main` 并推送，通过 Git 触发生产构建。开发分支推送生成预览，并不自动替换正式域名。

1. 用户检查本地差异，提交并推送 `feat/art-samples`。确认新提交的自动预览 READY，并试玩该提交；`6b1b1d9` 预览不能代替尚未提交成果的验收。
2. 核对项目应用根目录 `source/`、Git 关联仓库和 Production 分支跟踪是否为 `main`。查询工具未返回完整设置，本阶段没有代用户更改这些字段。
3. 用户同步、审查两分支差异，保留双方历史，普通合入 `main`；冲突解决和相关验证通过后推送。不要强推覆盖远端历史。
4. 在 [sinefine 的 Deployments](https://vercel.com/sereni1/sinefine/deployments) 核对 Git 触发的生产构建及完整提交。等待 READY，确认正式域名指向该生产部署，再验收两个新路由、顶栏入口、士郎进出卫宫宅、旧记录恢复和手机操作。

Git 自动发布依据：[Vercel Git 集成说明](https://vercel.com/docs/git)。此前提到的 [Promote to Production](https://vercel.com/docs/deployments/promoting-a-deployment) 可用于一次性发布，后续以主线推送为建议常规流程；本阶段没有执行任一种发布操作。
