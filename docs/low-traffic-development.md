# Sinefine｜低流量开发工作流

更新：2026-10-09。目标是减少重复上传，保留融合版 2.5D 的质量、功能、原始资源与必要测试。

## 已核对的边界

- **已在本地**：React/CSS 背景与人物绘制、Three.js 样板渲染、移动、碰撞、地面配准、寻路、浏览器预览、类型检查和自动测试。街区图片从本地 `public/fate/` 读取；当前城市场景加载有缓存、相邻街段预加载与手动失败重试，不存在每帧上传模型的项目代码。
- **仍需云端**：Codex 推理与必要视觉分析；确需新素材时的 AI 绘图；用户开启的真实 DeepSeek、云端存档／后台代管；Git 同步和 Vercel 发布。保留这些能力，避免把本地检查改成远程服务。
- 此前只读调查在本机 `logs_2.sqlite` 找到本聊天 10 月 8 日约 20:28—21:46 的 **62 条压缩请求体统计**：单次约 42—77 MB、合计约 2.71 GB。这是请求体日志，不能直接等同于 TCP 实发或代理账单；更早日期没有同等字节证据，不能精确归因全部 95 GB。
- 同期会话压缩记录仍保留历史图片；旧执行记录中还存在用截图等待人物到场的循环。当前 `source/scripts/` 没有这种持续截图脚本，因此本轮防止**未来重复执行**，没有假称删掉不存在的持久循环。

## 每轮任务的做法

1. 在实际项目目录开启任务，读根 `AGENTS.md` 和 [精简交接](development-handoff.md)，确认当前目标和工作区差异。不要默认附加旧会话、截图集、原始会话 JSONL、完整进度史或备份目录。
2. 定位需要的组件／测试，用 `rg` 限定模块；长文件按行段、具体函数和差异读取。连续独立检查在本地汇总，工具结果只输出概况／失败片段；避免一次输出后被截断，再读一遍。
3. 查已有素材，先本地复用。渲染和测试在本机执行。先检查现有依赖与服务，不反复安装依赖、拉库、构建或创建同用途预览服务。
4. 功能验证优先状态：位置、目标、当前街段、镜头模式、加载结果、DOM 与焦点。等待用明确条件和截止时间；有等待 API 时直接等待，否则少量状态查询。没有进展输出一次诊断，不用截图／视觉模型做轮询。
5. 视觉判断才取图：常规只传压缩检查副本；必要时裁剪局部或看原图。仅截图修改后的关键状态，画面未实质变化不重复发送。保存的本地图可供用户看，但不要每轮自动附加给模型。
6. 必要自动测试照常保留。通过后，只有新改动、失败和未解决疑点才扩查／重跑。远程工具请求失败先诊断，代理主动重试同一请求最多一次；客户端内部重试不受仓库控制。等待与重试上限约束单个失败步骤，不限制正常任务完成。
7. 生成素材保存到项目并记录用途、视角、提示词／版本；相同需求引用已有文件。阶段结束更新交接的当前状态，历史详细记录按需链接，提交推送依用户授权。

## 本地素材与检查图工具

`source/scripts/art-workflow.mjs` 只做本地文件处理，无网络请求、自动上传、浏览器截屏或素材生成。产物位于已忽略的 `source/.verification/`，不会进入正式页面或默认 Git 提交。

在 `source/` 下运行：

```powershell
npm run art:inventory
npm run art:inventory -- --match shrine
npm run art:review -- public/fate/art-sample/要检查的图片.png
npm run art:review -- .verification/实际截图.png --crop 200,120,600,480
npm run art:review -- .verification/实际截图.png --detail
npm run test:workflow
```

- 素材索引：仅扫描 `public/fate/`，跳过符号链接；完整路径／尺寸／SHA-256 写到本地 JSON，终端仅给总数／大小。`--match` 按路径过滤，最多输出十条，完整结果仍留本地。不会遍历项目上下文或恢复档案。
- 检查副本：默认 JPEG、最长边 1280、质量 80；`--detail` 最长边 2560、质量 92。裁剪坐标按输入原图像素指定，不放大；透明图片在检查副本上铺中性底色，**原图不变**。
- 以输入内容哈希、裁剪和参数命名缓存；相同输入／参数返回同一副本路径，不重复编码。缓存命中不代表应该再次上传；代理仍按规则判断画面是否已看过。
- 检查图工具使用**已有 sharp**：优先项目依赖，其次运行当前 Node 的 Codex 捆绑包；也可用环境变量 `SINEFINE_SHARP_PATH` 指向已安装模块。缺库时明确报错，不自动安装／下载。Codex 可通过工作区依赖工具定位本机捆绑 Node 后直接运行脚本，不把本机绝对运行时路径写入项目。
- `art:inventory` 无额外依赖；尺寸只解析 PNG 头，其余格式的尺寸记为未知，绝不联网补信息。索引中的原文件哈希用来识别已保存素材。

## 客户端限制与用户需要做的事

项目规则可以减少新读取和新截图，**不能删除当前聊天已由客户端附加的历史图片、控制底层请求体、强制改变压缩策略或关闭客户端重连**。也不能靠删本地缓存或把已有大图压缩，追溯减小历史消息中的图片。本轮未改客户端／代理设置、删聊天记录或停止用户服务。

浏览器工具若自动回传首屏或原始截图，也不能靠后续生成 JPEG 收回已发送的内容；应优先用不回传像素的状态检查，能先本地保存时再准备检查副本。工具或客户端强制附加的内容单独注明，不假装已受脚本拦截。

下一大型阶段请在 Codex **新建普通任务**，选择当前实际仓库 `D:/projects/sinefine` 的本地项目与正确分支；不要分叉／导入旧长聊天。新建不会自动替你迁移未提交改动，因此使用当前本地目录并检查状态，不假定新工作树含有这些改动。[OpenAI Docs 的项目规则说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明规则按目录加载；应从此项目启动，避免只在 `D:/` 根目录启动后依赖自动发现。

只发送这段短提示，并填本轮目标：

```text
继续 Sinefine，仓库 D:/projects/sinefine，分支 feat/art-samples。
先读根 AGENTS.md 和 docs/development-handoff.md，检查 Git 状态。
按本地执行、云端辅助规则推进，不导入旧聊天或历史图片，不 commit/push。
本轮目标：……
```

AGENTS 约束的是执行习惯，不是流量防火墙。当前聊天历史是否仍随请求重传，应由实际日志验证；已有压缩也曾保留图片，不能保证再次压缩会剔除图片。此处不承诺流量降低百分比。

新会话启动后，可在**本地只读**汇总少量请求日志的 `pre_compression_bytes` / `post_compression_bytes`，并结合代理按进程／目标的实发字节计数，与此前样本比较；不要把原始请求正文或完整日志发给模型。`estimated_bytes` 是日志占用，输入 token／磁盘文件大小也不是网络字节。若客户端仍异常附加旧图片或不断重连，用户可联系 OpenAI 支持提供脱敏的时间、版本与字节统计，项目规则无法代替客户端修复。
